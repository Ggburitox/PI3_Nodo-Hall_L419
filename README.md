# GEMELO DIGITAL L419 — KY-024

1. Enciende el gateway con gateway_ap.ino. Confirma que su red se llama GEMELO-L419 y su MAC STA coincide con 58:2A:BD:72:03:DC. Si no coincide, cambia MAC_GATEWAY en nodo_magnetico.ino. No hace falta contraseña en el nodo.
2. Abre nodo_magnetico/nodo_magnetico.ino en Arduino IDE. El paquetes.h original está en la misma carpeta, no modificarlo. Placa DOIT ESP32 DEVKIT V1 (o ESP32 Dev Module si corresponde), puerto USB. VCC 3.3 V, GND común, DO GPIO32, AO GPIO34. Retira el imán durante la calibración y sube el código. Si no detecta la red al arrancar, reinicia con el gateway encendido.
3. Monitor serie a 115200. Imán cerca = cerrada, lejos = abierta. El contador local aumenta una sola vez por transición cerrada->abierta. Al iniciar no se cuenta una apertura ficticia. Mantener la puerta abierta 60 s activa el bit 1 (valor decimal 2). Última columna 1 = último resultado de envío satisfactorio a nivel MAC, 0 = fallo o aún no enviado. Verificar recepción e interpretación en la API.
4. Conecta la laptop a GEMELO-L419 (contraseña de la guía: gemelo2026). Abre http://192.168.4.1/api/ultimos y comprueba nodo 6, tipo magnetico. No hay Internet en esa red.
5. En una terminal dentro de Hall_L419_final ejecuta python3 interfaz.py. Abre http://127.0.0.1:8765 si no se abre automáticamente. Para probar sin hardware: python3 interfaz.py --demo. Si tienes el simulador de la guía corriendo en el puerto 8000: python3 interfaz.py --gateway http://localhost:8000. Sin dependencias externas.
6. El panel consulta /api/hora al iniciar, /api/ultimos y /api/datos?desde=...; marca inactivo cuando hace_s > 60. El campo campo_raw aparece sólo si el gateway lo publica. El histórico suma aperturas de hasta 60 paquetes recibidos, no es el total de toda la vida del nodo. El tiempo mostrado es el del último intervalo, no la duración acumulada de la apertura actual.

DECISIONES: lectura cada 500 ms como el programa probado; envío cada 2000 ms (ajustable); umbral 80 (ajustable); apertura prolongada 60 s (provisional). Conteos/tiempos del paquete corresponden a ventanas disjuntas de envío; un paquete perdido pierde sus datos y seq permite detectarlo. En monitor serie se muestran además acumulados locales. El muestreo puede perder aperturas inferiores a 500 ms. El bit MAG_BIT_FALLO está disponible pero no se activa sin diagnóstico eléctrico validado; el panel sí muestra anomalías informadas y desconexiones. MAC de ejemplo pendiente de confirmar. No se necesita espnow_nodo.h. No se ha compilado con un toolchain ESP32 ni probado físicamente con el gateway.
